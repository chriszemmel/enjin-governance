# Chain flow

How we connect to the Enjin Relaychain, how connections are cached, and how
they fail over.

## Endpoints

Configured in `lib/chain/chains.ts`. Sourced from `lib/env.ts`.

| Chain | Primary | Fallback |
|---|---|---|
| Enjin Relay | `NEXT_PUBLIC_ENJIN_RELAY_WSS` | `NEXT_PUBLIC_ENJIN_RELAY_FALLBACK_WSS` |
| Enjin Matrix | `NEXT_PUBLIC_ENJIN_MATRIX_WSS` | `NEXT_PUBLIC_ENJIN_MATRIX_FALLBACK_WSS` |
| Canary Relay | `NEXT_PUBLIC_CANARY_RELAY_WSS` | - |
| Canary Matrix | `NEXT_PUBLIC_CANARY_MATRIX_WSS` | - |

Mainnet defaults point at Enjin's public RPC. For production traffic, host
your own or use a paid Dwellir / OnFinality endpoint.

## Connection lifecycle (`lib/chain/api.ts`)

```ts
const api = await getApi("wss://rpc.relay.blockchain.enjin.io")
```

`getApi(endpoint)` returns a cached `ApiPromise` keyed by endpoint URL.

- **First call**: opens a `WsProvider` with a 10s connect timeout and a 15s
  metadata-ready timeout. Both must succeed; otherwise the call retries up to
  3 times with a 1s delay before throwing.
- **Subsequent calls (same endpoint)**: returns the cached instance
  immediately. If the cached instance reports `!isConnected`, it is evicted
  and re-created.
- **Disconnection**: caller-controlled. Server-side handlers should
  `await api.disconnect()` in a `finally` block to free the websocket. The
  browser client keeps the connection open for the lifetime of the page -
  the cache is the persistence layer.

## Fallback (`lib/chain/connect.ts`)

For one-shot reads where you don't want to rely on the long-lived pool
(e.g. server components, edge functions), `createApiWithFallback(primary, fallback)`
races primary→fallback:

1. Try primary with a 10s timeout.
2. On timeout or connect error, try fallback with the same 10s timeout.
3. On second failure, throw.

The pool itself does not fall back - if you need automatic failover, use
`createApiWithFallback` for the lifetime of that operation. The MVP uses
the pool for browser-side reads and accepts that a single endpoint outage
will surface as a query error (React Query retries handle most cases).

## WASM init (`lib/chain/ss58.ts`)

`@polkadot/util-crypto` requires a WASM module that initializes
asynchronously. Call `initializeWasm()` (cached idempotent
helper) before any address encode/decode/sign/verify. This is automatic in
the client bundle (Next.js bundles + the module self-initializes on import)
but must be called explicitly in serverless functions on cold start.

## Browser bundle notes

`@polkadot/api` brings in Node built-ins (`fs`, `net`, `tls`). `next.config.mjs`
sets `webpack.resolve.fallback = { fs: false, net: false, tls: false }` so
the browser bundle excludes them. Without this, you get a build error.

Server-side, `serverExternalPackages: ["@polkadot/api", "@polkadot/util",
"@polkadot/util-crypto"]` tells Next.js to import these from `node_modules`
at runtime rather than bundling them - otherwise the WASM init breaks.

## CSP

The `connect-src` directive in `next.config.mjs` includes:
- `wss://rpc.relay.blockchain.enjin.io` (and the fallback host)
- `wss://relay.walletconnect.com`
- `https://*.walletconnect.com https://*.walletconnect.org` (registry / metadata)
- `https://enjin.subscan.io` (deep links + optional enrichment)

If you add an endpoint or external service, update `connect-src`.

## Event matching (`lib/chain/events.ts`)

After `signAndSend`, the subscription callback yields a `SubmittableResult`
whose `events: Vec<EventRecord>` carries the on-chain events generated by
the extrinsic. We match these against known pallet events to decide what
happened.

```ts
const submitted = result.events.find(({ event }) =>
  api.events.referenda.Submitted.is(event),
)
if (submitted) {
  const [index, track, hash] = submitted.event.data
  // ...
}
```

`isDiscardedError` (`lib/chain/events.ts`) recognizes the family of
"State already discarded" / "Unknown block" errors that occur when reading
old finalized blocks - treat them as soft errors and skip rather than fail
the page.

## Archive RPCs

For terminal referenda the primary RPC has often pruned the call
preimage from live state. `lib/chain/chains.ts` configures a dedicated
archive endpoint per chain (`wss://archive.relay.{blockchain,canary}.enjin.io`)
and `lib/query/hooks/use-archive-api.ts` exposes a separate
ApiPromise that historical reads route through. The voter-list query
also runs against the archive at `finalisation_block - 1` for
terminal refs so the entry set is complete.
